## Phase 3: Product and security review (observed behaviour)

**First-time usability.** The homepage explains the 6 steps and has one clear call to action. The dashboard opens with the new-case form; the case page goes straight to "Upload the agreement". After upload the Signature tool is preselected, a banner says "Click on any page where the signature should go", and "Create signing link" explains that fields lock. The link panel has an incognito tip and the page turns Completed by itself. I reached a signed PDF without reading any docs. I found no dead ends: every error state (invalid, incomplete, revoked, expired or used link; bad upload) says what happened and what to do.
- Minor: after placing one field the tool deselects, so the next field needs another tool click. This seems intentional, but is worth knowing.

**Signer instructions.** The intro names the sender, the case and the pages to sign. Fields pulse "Sign here" and show a live preview of the signature in place. The consent text is explicit, and the submit button stays disabled with a reason until name, signature and consent are all present.

**Loading and errors.** Upload shows progress, save state shows "Unsaved changes" → "Saved", and link creation and signing show busy labels. No console errors were seen on any admin or signer page.

**Privacy and isolation.** Every admin resource tried from another workspace returned 404 (ADV-24…29). The cookie is httpOnly, Secure, SameSite=Lax and lasts 30 days.

**Token exposure.** The token sits in the URL fragment, which the browser never sends to the server. Across a full signer session (page, PDF fetches and submit), **no request URL contained the token**. It is not stored in localStorage, sessionStorage or cookies. `Referrer-Policy: no-referrer`, X-Frame-Options DENY, nosniff and HSTS are present; there is **no Content-Security-Policy** (Q-6). `/api/sign/view` returns `Cache-Control: no-store` (measured). PDF responses set `private, no-store` in `src/lib/server/http.ts`; I didn't measure this separately. Error responses use `public, max-age=0, must-revalidate`, so nothing is cached. The admin can redisplay a pending link by design; the server stores it encrypted and clears it on completion or revoke.

**Fit with the client requirement.** All seven demo steps in CLAUDE.md and the brief were observed on production: public URL, self-service workspace, unseen multi-page PDF, visual placement on any page with correction, copyable link, separate-browser signing with consent and a single submit, Completed status with the stamped PDF at the placed coordinates, a server event log, and no re-signing.

**Reusable agreement templates: feasible but not worth it before the deadline.**
- *Minimal version:* "save this case's field layout as a template" plus "apply template". Applying would only make sense to a PDF with the same page count and page sizes. It needs a table, 2 routes, UI on the case page, a mismatch check and tests, roughly 3–4 h including production verification.
- *Evaluator value:* low. The evaluator uploads one unseen MIND PDF, and placing a field takes about 5 s. Templates don't show in the graded flow but add new failure modes (applying to a different layout lands fields in the wrong place).
- *Recommendation:* don't build before the deadline. List it as the first post-deadline item in the roadmap.

## Findings and recommendations (ranked by evaluator impact)

| ID | Sev | Finding | Recommendation | Effort / risk |
|---|---|---|---|---|
| Q-1 | P1 | Name/date fields and the certificate use standard Helvetica (WinAnsi). Characters outside it print as `?`, e.g. CJK, `Ł`, Cyrillic. The stored and displayed name is correct and the signature image is correct, but the PDF evidence is lossy. The signer isn't warned. Already documented as a limitation. | Short term: none needed for an English-language MIND demo; keep it documented. Proper fix: embed a Unicode TTF via `@pdf-lib/fontkit` (Noto Sans covers Latin/Greek/Cyrillic in ~0.5 MB; CJK needs a ~10 MB+ font or subsetting). | 1–2 h for Latin-Ext/Cyrillic, more for CJK; touches stamping, so needs full regression |
| Q-2 | P2 | A reload within ~0.7 s of placing a field can drop that field, if the user confirms the beforeunload prompt | Flush the pending save on `pagehide` with `fetch(..., {keepalive:true})` | 30 min, low risk |
| Q-3 | P2 | "Replace PDF" silently discards already-placed fields | `confirm()` when fields exist | 15 min, low risk |
| Q-4 | P2 | A submit on an expired link is logged as "Rejected attempt to reuse a closed link" | Log the reason (expired / revoked / completed) | 20 min |
| Q-5 | P2 | The certificate page is always US Letter, even for A4 documents | Use the last page's size | 15 min, touches stamping |
| Q-6 | P2 | No Content-Security-Policy header | Add a CSP (worker-src, blob: for downloads, data: for the signature preview) | 1 h with testing, moderate breakage risk |
| Q-7 | P2 | No rate limiting on workspace creation or uploads | Vercel Firewall rate-limit rule or a simple per-IP DB counter | 30–60 min |
